Tipo de projeto: este grupo não dá continuidade a um sistema anterior. O Torcida é um projeto novo. Por isso, todas as funcionalidades abaixo são novas. Nenhuma está implementada ainda (o código do MVP será feito nas próximas entregas).

1. Identificação do projeto

NomeTorcida — rede social de futebol
ProblemaTorcedor comenta o time em redes genéricas; não há time de coração nem ranking da torcida na plataforma.
SoluçãoFeed estilo Twitter/Threads só de futebol, com time de coração, ranking e resumo do dia/chatbot.

3. Lista de requisitos funcionais

IDRequisito
RF01O sistema deverá permitir o cadastro de usuário com nome, e-mail, senha e time de coração.
RF02O sistema deverá exigir o time de coração como campo obrigatório no cadastro.
RF03O sistema deverá validar e-mail único, senha com mínimo de 6 caracteres e preenchimento dos campos obrigatórios.
RF04O sistema deverá permitir o login com e-mail e senha.
RF05O sistema deverá recusar o login quando o e-mail ou a senha estiverem incorretos.
RF06O sistema deverá permitir o logout.
RF07O sistema deverá impedir o acesso ao feed, ao ranking e ao resumo do dia sem autenticação.
RF08O sistema deverá permitir que o usuário autenticado crie um post em texto.
RF09O sistema deverá associar automaticamente a etiqueta do time de coração ao post.
RF10O sistema deverá permitir imagem no post de forma opcional.
RF11O sistema deverá listar o feed de posts em ordem cronológica inversa (mais recente primeiro).
RF12O sistema deverá exibir, em cada post, autor, time, texto, data, quantidade de curtidas e comentários.
RF13O sistema deverá limitar o texto do post a 280 caracteres.
RF14O sistema deverá permitir curtir um post.
RF15O sistema deverá permitir remover a própria curtida.
RF16O sistema deverá impedir mais de uma curtida do mesmo usuário no mesmo post.
RF17O sistema deverá permitir comentar um post.
RF18O sistema deverá listar os comentários de um post com autor e data.
RF19O sistema deverá exibir o ranking de torcida, ordenado pela quantidade de usuários cadastrados em cada time.
RF20O sistema deverá mostrar posição, nome do time e número de torcedores.
RF21O sistema deverá atualizar o ranking automaticamente quando um novo usuário se cadastrar.
RF22O sistema deverá exibir um card fixo “Resumo do dia” com texto referente ao time de coração do usuário logado.
RF23O sistema deverá montar o resumo do dia a partir dos jogos cadastrados no banco e, quando houver, de posts recentes daquele time.
RF24O sistema deverá oferecer um chatbot para o usuário perguntar quais jogos há no dia.
RF25O sistema deverá permitir que o chatbot informe o resumo do time de coração do usuário.
RF26O sistema deverá responder com mensagem clara quando não houver jogos cadastrados para a data.
RF27O sistema deverá permitir que o administrador cadastre times (nome e sigla).
RF28O sistema deverá permitir que o administrador cadastre jogos do dia (mandante, visitante, data, horário e, se houver, placar).
RF29O sistema deverá listar os times disponíveis para escolha no cadastro do torcedor.

5. Regras de negócio

IDRegra
RN01Cada usuário possui exatamente um time de coração nesta versão.
RN02A etiqueta do post é sempre o time de coração do autor; o usuário não escolhe outro time na hora de postar.
RN03O ranking conta usuários cadastrados por time, não o número de posts.
RN04Jogos do dia são os registros cuja data é a data atual do sistema.
RN05Apenas o administrador cadastra times e jogos.
RN06Post sem texto não pode ser publicado.
RN07Comentário vazio não pode ser enviado.
